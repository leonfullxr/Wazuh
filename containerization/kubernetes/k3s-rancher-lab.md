# Wazuh on k3s with Rancher Management (Vagrant Lab)

A reproducible two-VM lab: Wazuh (manager, indexer, dashboard) from the
official `wazuh-kubernetes` manifests on a single-node k3s cluster, and a
standalone Rancher server in a second VM that imports the cluster for a web UI
(pod health, logs, shells, rolling restarts). Rancher gets its own VM so it
does not compete with the Wazuh indexer for CPU, memory, and disk I/O.

> Applies to Wazuh 4.14.x (`wazuh-kubernetes` tag `v4.14.5` checked), k3s,
> Rancher v2.x in Docker, Vagrant + VirtualBox on a Windows or Linux host.
> This is a lab build: default credentials, self-signed certificates,
> single node. Do not expose it as is.

## Layout and sizing

```
Host (VirtualBox, host-only network 192.168.56.0/24)
+-- VM wazuh-k3s   4 vCPU, 7 GB   k3s + wazuh namespace (manager, indexer, dashboard)
|                                 cattle-system (Rancher cluster agent) --+
+-- VM rancher     2 vCPU, 6 GB   docker: rancher/rancher  <--------------+  HTTPS 443
```

- At least 13 GB of free host RAM and about 40 GB on an SSD. OpenSearch and
  Rancher are both I/O heavy; on a spinning disk Rancher fails its own startup.
- A 16 GB host running both VMs plus a browser will swap. Close heavy apps or
  run one VM at a time.
- Optional, on Windows: put new VM disks on the SSD with
  `VBoxManage setproperty machinefolder "<SSD_DRIVE>\VBoxVMs"`.

| Variable | Meaning | Example |
|---|---|---|
| `<WAZUH_VM_IP>` | Wazuh/k3s VM, host-only network | `192.168.56.10` |

| `<IMPORT_URL>` | Import manifest URL generated by Rancher | `https://<RANCHER_VM_IP>/v3/import/<token>.yaml` |

## Step 1: Wazuh on k3s

`Vagrantfile` for the Wazuh VM:

```ruby
Vagrant.configure("2") do |config|
  config.vm.box      = "bento/ubuntu-24.04"
  config.vm.hostname = "wazuh-k3s"
  config.vm.network "private_network", ip: "<WAZUH_VM_IP>"
  config.vm.provider "virtualbox" do |vb|
    vb.name   = "wazuh-k3s"
    vb.memory = 7168
    vb.cpus   = 4
  end
  config.vm.provision "shell", path: "provision.sh", env: { "VM_IP" => "<WAZUH_VM_IP>" }
end
```

`provision.sh` next to it:

```bash
#!/usr/bin/env bash
set -euo pipefail
VM_IP="${VM_IP:?}"

# OpenSearch (Wazuh indexer) kernel requirements
sysctl -w vm.max_map_count=262144
echo 'vm.max_map_count=262144' > /etc/sysctl.d/99-wazuh.conf
swapoff -a || true

# bento boxes leave about half the disk unallocated: grow the root LV,
# otherwise the node hits DiskPressure and pods stay Pending
if command -v vgs >/dev/null 2>&1 && vgs ubuntu-vg >/dev/null 2>&1; then
  lvextend -l +100%FREE /dev/ubuntu-vg/ubuntu-lv || true
  resize2fs /dev/ubuntu-vg/ubuntu-lv 2>/dev/null || xfs_growfs / 2>/dev/null || true
fi

apt-get update -y && apt-get install -y curl openssl git ca-certificates

# k3s bound to the host-only IP, with that IP in the API certificate
curl -sfL https://get.k3s.io | INSTALL_K3S_EXEC="--node-ip ${VM_IP} --tls-san ${VM_IP}" sh -
```

Start it with `vagrant up`, then inside the VM (`vagrant ssh`, `sudo -i`):

```bash
export KUBECONFIG=/etc/rancher/k3s/k3s.yaml
git clone --depth 1 -b v<WAZUH_VERSION> https://github.com/wazuh/wazuh-kubernetes.git /opt/wazuh-kubernetes
cd /opt/wazuh-kubernetes
```

The `local-env` overlay patches the StorageClass to `microk8s.io/hostpath`.
k3s ships the `rancher.io/local-path` provisioner instead, so replace the patch:

```bash
cat > envs/local-env/storage-class.yaml <<'YAML'
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: wazuh-storage
provisioner: rancher.io/local-path
volumeBindingMode: WaitForFirstConsumer
reclaimPolicy: Delete
YAML
```

Generate certificates and deploy:

```bash
bash wazuh/certs/indexer_cluster/generate_certs.sh
bash wazuh/certs/dashboard_http/generate_certs.sh
kubectl apply -k envs/local-env/
kubectl -n wazuh get pods -w     # wait for every pod 1/1 Running
```

The indexer image is large; the first pull keeps the pod in `PodInitializing`
for several minutes. That is expected.

### Initialize the indexer security index (only if needed)

If the dashboard returns HTTP 503 and the indexer log says
`Not yet initialized (you may need to run securityadmin)`, run `securityadmin`
once. The result persists on the indexer volume.

```bash
POD=wazuh-indexer-0
PODIP=$(kubectl -n wazuh get pod $POD -o jsonpath='{.status.podIP}')
kubectl -n wazuh exec $POD -- bash -c "
  export JAVA_HOME=/usr/share/wazuh-indexer/jdk
  B=/usr/share/wazuh-indexer
  \$B/plugins/opensearch-security/tools/securityadmin.sh \
    -cd \$B/config/opensearch-security -icl -nhnv \
    -cacert \$B/config/certs/root-ca.pem \
    -cert   \$B/config/certs/admin.pem \
    -key    \$B/config/certs/admin-key.pem \
    -h $PODIP -p 9200"
```

> Keep `B=...` on its own line. Written as `B=/path $B/plugins/...` on one
> line, `B` is only a prefix assignment for that command and `$B` expands
> empty, so the script path resolves to `/plugins/...` and fails.

## Step 2: Access the dashboard

The `dashboard` Service is `type: LoadBalancer` on port 443. On k3s, Traefik
already holds 443 through ServiceLB, so the dashboard's external IP can stay
`<pending>`. Use its NodePort instead:

```bash
kubectl -n wazuh get svc dashboard     # PORT(S) 443:<NODEPORT>/TCP
```

Open `https://<WAZUH_VM_IP>:<NODEPORT>`, accept the self-signed certificate,
and log in as `admin` with the indexer password from
`wazuh/secrets/indexer-cred-secret.yaml` (repo default `SecretPassword`).
Change the default secrets in `wazuh/secrets/` before anything beyond a lab.

## Step 3: Standalone Rancher

`Vagrantfile` for the Rancher VM (in its own folder):

```ruby
Vagrant.configure("2") do |config|
  config.vm.box      = "bento/ubuntu-24.04"
  config.vm.hostname = "rancher"
  config.vm.network "private_network", ip: "<RANCHER_VM_IP>"
  config.vm.network "forwarded_port", guest: 443, host: 8443, id: "rancher-https"
  config.vm.provider "virtualbox" do |vb|
    vb.name   = "rancher"
    vb.memory = 6144
    vb.cpus   = 2
  end
  config.vm.provision "shell", path: "provision-rancher.sh",
    env: { "BOOTSTRAP_PASSWORD" => "<BOOTSTRAP_PASSWORD>", "RANCHER_VERSION" => "<RANCHER_VERSION>" }
end
```

`provision-rancher.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail
: "${BOOTSTRAP_PASSWORD:?}" "${RANCHER_VERSION:?}"

if command -v vgs >/dev/null 2>&1 && vgs ubuntu-vg >/dev/null 2>&1; then
  lvextend -l +100%FREE /dev/ubuntu-vg/ubuntu-lv || true
  resize2fs /dev/ubuntu-vg/ubuntu-lv 2>/dev/null || xfs_growfs / 2>/dev/null || true
fi

curl -fsSL https://get.docker.com | sh     # review the script first outside a lab
systemctl enable --now docker
docker run -d --name rancher --restart=unless-stopped \
  -p 80:80 -p 443:443 --privileged \
  -e CATTLE_BOOTSTRAP_PASSWORD="${BOOTSTRAP_PASSWORD}" \
  rancher/rancher:${RANCHER_VERSION}
```

Start it with `vagrant up`. Open `https://<RANCHER_VM_IP>` (or
`https://localhost:8443`), log in as `admin` with the bootstrap password, set a
new password, and set the Server URL to `https://<RANCHER_VM_IP>`.

> The Server URL must be an address the Wazuh VM can reach. If it is left as
> `localhost`, the cluster agent on the Wazuh VM connects to itself and the
> import never becomes Active.

## Step 4: Import the cluster into Rancher

1. From the Wazuh VM, confirm Rancher is reachable (expect `200`):

   ```bash
   curl -sk -o /dev/null -w '%{http_code}\n' https://<RANCHER_VM_IP>/ping
   ```

2. In Rancher: Cluster Management, Import Existing, Generic. Name it
   `wazuh-k3s`, click Create, and copy the `--insecure` registration command
   (needed because the Rancher certificate is self-signed).

3. If this k3s cluster was imported into a Rancher before, clear the leftovers
   first (see [Troubleshooting](#troubleshooting)).

4. Apply it on the Wazuh VM and wait for the agent:

   ```bash
   curl --insecure -sfL <IMPORT_URL> | kubectl apply -f -
   kubectl -n cattle-system rollout status deploy/cattle-cluster-agent
   ```

5. Verify on the Rancher VM. The cluster should show `Ready=True` and
   `Connected=True`, and the UI lists it as Active next to `local`:

   ```bash
   docker exec rancher kubectl get clusters.management.cattle.io
   ```

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Pods `Pending`, node taint `disk-pressure` | Root LV left at half the disk by the bento box | Grow the LV (provisioner above); reclaim images with `k3s crictl --timeout 300s rmi --prune` |
| Dashboard HTTP 503, indexer log `Not yet initialized` | Security index never bootstrapped | [Run securityadmin](#initialize-the-indexer-security-index-only-if-needed) |
| `securityadmin.sh: No such file or directory` | `B=` and `$B` on the same command line | Put the assignment on its own line, as above |
| `dashboard` Service `EXTERNAL-IP <pending>` | Traefik already owns 443 on ServiceLB | Use the NodePort, or disable Traefik (`--disable traefik`) |
| Rancher container restarts (exit 137) at `Restoring git repositories` | Slow disk or too little RAM starves startup | Run the Rancher VM on SSD with 6 GB or more |
| `vagrant up`: `timeout during server version negotiating` | Host RAM over-committed, guest paged out | Free host RAM, `vagrant reload` once, then `vagrant ssh -c "sudo bash /vagrant/provision-rancher.sh"` |
| Import fails: `namespace cattle-system is being terminated` or `rancher-webhook not found` | `cattle-*` namespaces stuck Terminating from a previous Rancher | Clear them with the commands below |

Clearing stuck Rancher leftovers (deletes Rancher webhooks and strips
finalizers from every Terminating namespace, so check the list first):

```bash
kubectl get ns | awk '$2=="Terminating"'
for kind in validatingwebhookconfiguration mutatingwebhookconfiguration; do
  kubectl get $kind -o name | grep -iE 'rancher|cattle' | xargs -r kubectl delete --ignore-not-found
done
for ns in $(kubectl get ns --no-headers | awk '$2=="Terminating"{print $1}'); do
  kubectl get ns "$ns" -o json \
    | python3 -c "import sys,json;d=json.load(sys.stdin);d['spec']['finalizers']=[];print(json.dumps(d))" \
    | kubectl replace --raw "/api/v1/namespaces/$ns/finalize" -f -
done
```
