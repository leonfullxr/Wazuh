# AI SOC contracts - v1.4

Canonical service and wire contract. This document defines the public models, ports, state operations, and behavioral limits used by the implementation. All limit values are explicit operator settings with specified defaults; live values require validation before enablement.

## 1. Conventions

Public types are strict, versioned contracts. Service packages separate contracts, content, planning, identity, query, state, judgment, application, API, MCP, telemetry, feedback and validation. Modules consume shared interfaces through `ai_soc.contracts.models`, `.ports` and `.errors`; application composition connects their implementations.

All public Pydantic objects are strict, `extra='forbid'`, frozen, JSON-serializable and schema-versioned (wire schema_version remains '1'; current freeze revision is '1.16'). Datetimes require timezone offsets, serialize to UTC `Z`, and never default to the system local timezone. IDs are opaque UUIDs except content IDs: lowercase `[a-z][a-z0-9_-]{0,63}`. Lists preserve named-topic order. Counts are integers >=0; exactness is explicit. Null means unavailable, never zero. Booleans do not coerce to counts. Dictionaries below have specified typed value domains, not arbitrary executable structures. All fields are required unless marked `?`; optional fields have stated defaults. Error codes are enums, not backend exception text.

Fixture builds have explicit `mode:'fixture'` in enclosing deployment config; invented digests never claim production provenance. |

`EvidencePack` (internal) = `{schema_version:'1',question_id,environment_id,topic_id,policy_hash,content_sha,fetches:list[FetchResult],checks:list[CheckResult],items:list[EvidenceItem],sha256}`. It has no duplicate allowed-template field: `ValidationContext` supplies approved templates. Multiple fetch windows remain in their FetchResult; there is no misleading single pack window. Hash canonical payload excluding sha256. No other topic or previous evidence enters a pack. The query layer materializes items in FetchResult/PlaybookRun; the application layer assembles and verifies a pack, never invents missing IDs.

`JudgmentRequest.finding_templates` is a tuple of complete approved `FindingTemplate` definitions, defaulting to empty. The engine supplies the topic-local catalog selected for `ValidationContext`; the runner captures strict canonical definitions before its first await and reconstructs separate counting, invocation and validation views. The existing approved topic-context system block includes IDs, kinds, binding fields, evidence kinds, prerequisite outcomes, relations and both localized texts before the second cache checkpoint. The model still proposes structured candidates; the independent validator owns acceptance and rendered prose.

An empty, invalid or oversized runtime catalog yields `evidence_unavailable` with a non-retryable configuration left-out before counting or reservation, preserving usable tables and checks. Approved prerequisite references must be declared in the associated topic playbook at content build and load. A declared check absent from this run, unknown, not configured or different from the required outcome remains evidence state: retain the full valid catalog and reject only unsupported candidates. Existing denial precedence applies. Direct provider entry points reject invalid catalogs locally before SDK/admission work.

The catalog is limited to 20 definitions per topic. The complete emitted `APPROVED TOPIC CONTEXT (data): ` label plus canonical topic-context JSON is limited to 65,536 UTF-8 bytes, including existing prose, JSON escaping and both localized template texts. Content build/load validates both language contexts. Exact token counting and the existing output-plus-256 context limit still apply. Oversized definitions are rejected without truncation. EvidencePack and TopicPromptPack shapes and hash algorithms remain unchanged; source identities retain their existing algorithms.

New content builds emit one `pack/finding-templates/{template_id}.json` record per approved definition and reject duplicate generated output paths. Other record groups retain their existing layout. The loader accepts verified legacy filenames when their payloads pass current semantic checks.

`DomainError` = `{code:ErrorCode,message:str,retryable:bool,trace_id:str,details:dict[str,str|int|list[str]]}`; details use whitelisted public keys only. Do not include URLs, credential-bearing backend errors, stack traces, raw JWTs or hidden index names.

`VerifiedPrincipal` = `{issuer:HTTPSUrl,sub:str,owner_key:SHA256,groups:tuple[str,...],edge:'browser'|'mcp'|'fixture',authenticated_at:UTCDateTime,expires_at:UTCDateTime,assertion_hash:SHA256}`. Only verifiers can construct it in production composition. `AuthorizedSite` = `{config:SiteConfig,backend_roles:tuple[str,...],visibility:'full'|'filtered'|'unknown',config_hash:SHA256,policy_hash:PolicyHash}`. `IndexerCredential` is an opaque secret wrapper with redacted repr, `{bearer_token:SecretStr,expires_at:UTCDateTime,key_id:str}`; not a response model.

Registry entries with missing CA, duplicate ID, unknown role, public-origin literal IP, URL userinfo/path/query, placeholder live ARN, or no approved private routing are invalid. DNS resolution and routing verification are live gates; private-looking DNS is not proof.

`ModelCapability` = `{id:str,label:str,region:str,resource_arns:tuple[str,...],context_tokens:int,max_output_tokens:int,count_tokens_model_id:str,efforts:tuple[Effort,...],effort_transport:'none'|'additionalModelRequestFields',effort_parameters:dict[Effort,dict[str,JSONScalar]],output_strategy:'strict_json_messages',count_strategy:'count_tokens_converse',count_contract_sha256:SHA256,cache_min_tokens:int,cache_max_checkpoints:int,cache_ttl:'5m'|'1h',validated_at:UTCDateTime,primary_doc_url:HTTPSUrl}`. HTTP: 400 `BAD_REQUEST` malformed JSON/protocol or cursor; 401 `AUTH_REQUIRED|AUTH_INVALID|AUTH_EXPIRED` with bearer protected-resource challenge on MCP; 403 `SITE_DENIED|ORIGIN_DENIED|CSRF_DENIED|SCOPE_DENIED`; 409 `FOLLOWUP_CONFLICT|QUESTION_ACTIVE|IDEMPOTENCY_CONFLICT|POLICY_CHANGED|CONTENT_CHANGED`; 410 `FOLLOWUP_EXPIRED|CURSOR_EXPIRED`; 413 `REQUEST_TOO_LARGE`; 422 `REQUEST_COMPLEXITY|INVALID_SCHEMA|UNSUPPORTED_MODEL|UNSUPPORTED_EFFORT|INVALID_WINDOW|INVALID_FILTER`; 429 `BUSY|RATE_LIMITED` with Retry-After; 503 `DEPENDENCY_UNAVAILABLE|SERVICE_DISABLED|CONFIG_INVALID`. Missing natural-language slots and a judgment missing a subject are **200 clarify**, not a validation error. An authenticated site's fetch denial is **200 topic denied** within Answer; a whole site-membership denial is 403. For questions with no judgment job, syntactically valid model/effort identifiers are ignored; only judgment jobs validate their capabilities. Model failure preserves tables and becomes `partial`; indexer 401 is a fetch `unavailable` with code `INDEXER_AUTH_REJECTED`, never downgraded to another credential or relabeled user-site denial.

MCP framing uses SDK protocol errors for malformed method/schema (`-32600`, `-32601`, `-32602`); domain failures during a valid tools/call produce `isError:true` plus typed sanitized error content. Transport authentication failures remain HTTP 401/403. Return structuredContent with schema and a concise text representation; do not expose raw provider output. Pin negotiated protocol `2025-11-25`; unsupported explicit version ->400; compatibility for missing version follows the SDK's supported default. Stateless JSON responses are valid Streamable HTTP; authenticated GET returns 405 if unsolicited SSE is not offered. Session IDs and resumable replay are unnecessary for this release. DDB leases still protect question processing across replicas. [MCP transport specification](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports).




## 5. Evidence identities, effective policy and bounded values

Canonical encoding `C(value)` is UTF-8 JSON with sorted object keys, compact separators, ensure_ascii=false, no NaN, integers only for evidence numeric values, exact retained strings (no lossy normalization), UTC timestamps to microseconds ending Z, arrays in schema-defined order. Schema-defined sets (roles and item/cue IDs) sort lexically; values lists preserve provider order unless a field explicitly declares set semantics. Service canonicalization is defined by the public contract; producers do not supply private algorithms.

Evidence ID = `ev1_` + lowercase SHA256 of `C({v:1,question_id,environment_id,topic_id,fetch_id,check_id,kind,source,snapshot_key,values})`. Exactly one of fetch_id/check_id is non-null. Row source=`{index_alias,record_id}`; bucket source=`{group_field,key}`; count source=`{template_id,window,filters,scope:'matching_visible_records'}`; probe source includes `probe_kind` and canonical probe filters; check source includes step_id and operand evidence IDs. Values are actual allowlisted row/bucket/count/probe/check values, including count exactness (`relation`, `approximate`) in typed aggregate metadata. Check items include `outcome`, expectation ID/version and operand IDs. Unknown counts remain null, never count=0. Reserved aggregate fields: `count,outcome,matched_nothing,relation,approximate,bucket_key,operand_ids,expectation_id,expectation_version`. Their exact types are respectively int, outcome enum, list[FieldId], eq/gte, bool, str/int, list[EvidenceId], ContentId/null, str/null. All fields typed and extra keys forbidden.

`EvidenceItem.kind` is the row/aggregate/check discriminator; `EvidenceItem.source` has no nested discriminator. Producers emit one strict `EvidenceSource` alternative using exactly the shape above. The shared producer-seam oracle validates row, bucket, count, probe, and check source shapes and rejects added fields; canonical vectors are independently serialized from those shapes before comparison with the implementation.

KEV is one optional approved group at `pack/kev/cisa-kev.json`, sourced from `content/kev/cisa-kev.json` plus its retained raw `content/kev/raw-cisa-kev.json`. The importer reads only a local uncompressed CISA JSON catalog and never follows catalog URLs. Entries are unique and sorted by CVE. The normalized digest is SHA-256 of canonical `{normalizer_version,entries}`.

At load, the content group is digest-verified and becomes an immutable public-only CVE/date index. Lookup returns `hit`, `not_listed` or `invalid_cve`; an absent group is `unavailable`. Lookup and freshness are independent. `valid_from` is the maximum of publication, retrieval and approval. `expires_at` is publication plus 604800 seconds. Evaluation before `valid_from` is `not_yet_valid`; equality with expiry is `stale`. A later retrieval does not renew the age of old catalog bytes. A hit means known exploitation is listed, not that a host is compromised; a miss does not rule out exploitation.

The complete KEV group is limited to 131072 bytes and 4096 entries. Worst-case page provenance is limited to 16384 bytes. These annotation allowances are additive: a decorated page may reach 311296 bytes (262144 plus 49152), and an initial response may reach 1146880 bytes (1048576 plus 98304). MCP transport envelope accounting is separate from canonical model limits. Telemetry and model-input budgets do not increase.

The server adds one page context item and one subject context item for each returned vulnerability row/CVE member, after judgment and on detached outbound fetch results. It preserves row order and telemetry. Per-page additions are limited to 256 context items and 49152 canonical bytes; the initial answer is limited to 512 items and 98304 bytes across its admitted vulnerability fetches. If a page or initial answer exceeds either bound, it emits the page summary without subject items, reports unavailable coverage with reason `limit`, and keeps the original telemetry rows. Context items never enter the EvidencePack, prompt, model request, checks or referral selection. The lookup evaluates every page against the first fetch snapshot time. The displayed affected state and inventory scan age remain unknown.

An initial answer audit records typed KEV context-use counts, provenance hashes and activation proof in its attempted event before completion; the completed marker carries the same uses. A continuation page is released only after an attempted audit event acknowledges its input cursor hash, next cursor hash, response hash and context uses. An audit failure returns `503 AUDIT_UNAVAILABLE` without a page. Terminal continuation PITs are left to their bounded TTL so the same cursor can be retried after audit failure. Page audit records authorize a release attempt, not client receipt; they create no completion or follow-up state.

`record_age` says that at least one returned record is within `max_age_seconds` of the read time. It is existential over returned rows only: `passed` never shows source health, completeness, ingestion lag or scan freshness. Outcomes, in precedence order: `denied` when the fetch is denied; `unknown` when the fetch is unavailable (the error code is named), the window is not `rolling`, the window ends after the read time or more than 300 s before it, or no returned row has a strictly parsed timezone-aware timestamp inside `[window.start,window.end)`; otherwise `passed` when the age of the newest valid timestamp is at most `max_age_seconds` (equal passes) and `failed` when it is larger. Rows with missing, malformed, naive, out-of-window or exactly-at-`window.end` timestamps are counted in the explanation and never change the outcome. The explanation always states that only returned rows were used, and it notes first-page reads and approximate totals. The check snapshot keys on the source snapshot key, the read time, the step ID and `max_age_seconds`; the source fetch stays reachable through the check operands.

Build rules for finding templates that cite checks (applied at content build and load, and enforced again at runtime):

- A template that allows `check` evidence must declare at least one `required_check_outcomes` prerequisite. At runtime every check binding must cite one of the template's declared prerequisites, so a row-plus-check mix without a declared prerequisite is rejected.
- A template that cites a `record_age` check must have exactly one prerequisite, that check, with outcome `failed`, kind `observation`, `allowed_evidence_kinds` equal to `[check]` and exactly one binding. Any other template that cites a `record_age` check is rejected. Recency passes cannot gate findings in this release.

## 13. Compatibility

The wire schema remains version 1 across freeze revisions. Revisions add typed fields and internal accounting metadata while preserving defaults needed to decode existing records. Qualified row pagination orders by timestamp, concrete `_index`, then `_id`, with all three fields following the requested direction. Every returned hit must be an object whose sort tuple contains a string or integer timestamp (never boolean), followed by nonempty index and record IDs matching that hit. The cursor uses the last raw backend hit, including when an equivalent repeat was removed from displayed rows. Legacy two-part cursors and unsupported current tie-break profiles require a fresh query and are rejected before credential or backend work; decoding an old cursor does not authorize unsafe continuation. An unqualified profile, unsupported PIT, malformed boundary or cursor that exceeds its resource envelope preserves usable first-page evidence with no cursor and an explicit paging limitation. Backend sort capability still requires site-specific qualification. The generated schemas in `contracts/v1/models.schema.json` are authoritative for exact serialized layouts; the behavioral requirements are summarized in [the service specification](specification.md).

Existing feedback request, response and event wire fields remain unchanged. Old strict readers reject the additive `finding_templates` request field; it is not rolling wire compatible.
